## Summary

New Streamlit performance dashboard following APP-001's exact
page/data-module split. Two new app files + one new test file, no changes to
`src/experiments/`, `src/evaluation/calibration.py`, `src/observability/`, or
`src/market/`:

- `src/app/performance.py` -- data-loading/shaping module (pure functions, no
  Streamlit import, zero probability/metric/ROI computation). Three loaders:
  - `load_model_window_ranking(report)` -- shapes `report["ranking"]`
    (ML-007's model x window comparison) verbatim, labels every row
    `DEVELOPMENT_EVIDENCE_LABEL = "development evidence (pre-2026-holdout)"`.
  - `load_calibration_comparison(report)` -- shapes
    `report["calibration"]["variants"][method]["aggregate"]` (uncalibrated /
    sigmoid / isotonic) verbatim, same development-evidence label.
  - `load_prediction_history(store)` -- shapes OBS-001 journal enrichment
    records (`.records()`) verbatim: game_pk, prediction_timestamp,
    model_version, model_probability, predicted_home_win, actual_home_win,
    correct.
  - Neither function ever reads `report["holdout_2026"]` (a real key present
    in the committed repaired report, value `"not inspected"`) -- verified by
    a real test, not just absence-by-omission (see Tests below).
- `src/app/performance_page.py` -- thin `streamlit run` entry point. Reads
  `PERFORMANCE_REPORT_PATH` (default
  `reports/experiments/v1-repaired-a910017bac839af5.json`, the ADR-006
  evidence report) and `PREDICTION_JOURNAL_PATH` (default
  `state/predictions/journal.jsonl`, mirroring APP-001's
  `PREDICTIONS_STORE_PATH` / `state/predictions/daily.jsonl` convention).
  Renders three tables (model/window ranking, calibration comparison,
  prediction history) via `st.dataframe`, with an on-page caption stating the
  2026 holdout has not been evaluated. Zero probability/metric/ROI logic in
  this file.

  never persisted as a report or journal field. The OBS-001 enrichment record
  schema (`REQUIRED_ENRICHMENT_FIELDS`) also does not carry
  market_probability/edge -- only `model_probability`. Displaying it would
  require recomputing from the original PIPE-001 record, which the task
  forbids.

  precomputed ROI number anywhere in the repo (checked `src/market/engine.py`
  and both `reports/experiments/*.json` files). Nothing to load.
