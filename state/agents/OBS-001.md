## Summary

Added `src/observability/journal.py`: `attach_results(*, predictions, results,
enrichment_timestamp, store)` reads already-written PIPE-001 prediction
records (read-only) and appends a **separate** enrichment record per
prediction whose game has a result, keyed by the same
`(game_pk, prediction_timestamp)` identity PIPE-001 already uses. Enrichment
records carry `model_version`, `actual_home_win`, `predicted_home_win`
(derived from `model_probability >= 0.5`), and `correct`. Games without a
result yet are skipped (`SKIP_NO_RESULT`), not errored.

Store mechanics (append-only, idempotent identical re-write, conflict-raising
differing re-write) are **reused** directly from
`pipelines.daily.InMemoryPredictionStore` / `JsonLinesPredictionStore` /
`PredictionConflictError` (aliased as `InMemoryJournalStore` /
`JsonLinesJournalStore` / `JournalConflictError`) rather than
re-implemented -- the key shape is identical, so this is the same contract,
not a new one.

Deliberately does not touch `src/market` paper/backtest ROI metrics or
recompute predictions; it only reads PIPE-001 output and results.
