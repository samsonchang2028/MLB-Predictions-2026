## Pass/play indicator — no real threshold exists in the codebase

Confirmed by reading `src/market/engine.py` and `src/pipelines/daily.py` in
full: MARKET-001 computes edge/EV and stops there; no staking/pass-play
threshold concept exists anywhere upstream. `DEFAULT_EDGE_THRESHOLD = 0.02`
in `src/app/board.py` is an explicit, documented, **synthetic display-only**
default (`abs(edge) >= threshold` -> "PLAY"), not a business decision — the
module docstring and the Streamlit page's on-screen caption both say so. It
is a parameter (`edge_threshold`) so a future real policy can override it
without touching the board. Promote to a real policy via an ADR before this
is used as an actual recommendation.

## Known limitations

- `TEAM_ABBREVIATIONS` in `src/app/board.py` is a new static id->abbreviation
  map (marked `ponytail:`) since no such lookup exists anywhere in the repo;
  unrecognized ids fall back to `"Team {id}"` rather than failing.
- No default prediction-store path convention existed before this task;
  `state/predictions/daily.jsonl` was chosen to mirror the
  `state/data-certifications/` convention and is overridable via
  `PREDICTIONS_STORE_PATH`. No writer currently populates that path — PIPE-001
  callers choose their own store path today; an operator/orchestrator wiring
  PIPE-001 to write there (or exporting the env var) is a follow-up, not part
  of this task's scope.
- `odds_snapshot_timestamp` is displayed as-is (`str()`); `JsonLinesPredictionStore`
  serializes it to an ISO string, `InMemoryPredictionStore` keeps a `datetime`
  — both render fine, no normalization added since nothing required one format.
- Streamlit rendering itself (`daily_board_page.py`) is intentionally
  untested by unit tests per the task's own note that it's thin/display-only;
  it was instead smoke-tested end-to-end via a headless `streamlit run`.
