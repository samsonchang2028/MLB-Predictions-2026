operator, on a machine with the certified DuckDB build, to:

1. Ingest and certify the 2026 season under the same DATA-006/DATA-007 rules

2. Run `python scripts/holdout_2026.py --certification <path-to-that-artifact>`
   (optionally `--database`, `--output`, `--random-state`).
3. Record the resulting `reports/experiments/v1-holdout-2026.json` metrics in
   `state/CURRENT.md` and this file, and only then move ML-010 to done.

## Draft review notes (`src/evaluation/holdout.py`)

Reviewed the pre-existing draft critically before building on it; found no
bugs. Specifically verified:

- It never lets a 2026 row enter the training partition or influence
  preprocessing fit: `train_idx`/`test_idx` are built directly from
  `DEV_SEASONS` / `HOLDOUT_SEASON` membership, with redundant defensive
  chronology/overlap assertions, and there is no scaler/imputer in the
  XGBoost pipeline that could be fit across the combined rows anyway (leakage
  test `test_fit_is_isolated_from_2026_rows` proves the fitted model is
  byte-identical regardless of how 2026 rows are mutated).
- `require_locked_methodology` correctly refuses when the ADR-006 file is
  missing, not Accepted, or missing the lock section -- verified against
  both synthetic broken ADR files and the real
  `docs/decisions/ADR-006-v1-methodology-lock.md`.
- Reuse of `evaluation.runner._evaluate_fold` / `_vectorize` (underscore-
  prefixed) is appropriate as-is: this is intra-package reuse between two
  sibling modules in `evaluation/`, not a public API boundary crossing.
  Promoting them to public names would touch `runner.py`, its docstrings, and
  its existing tests for no behavioral gain -- left unchanged per the
  anti-bloat "don't rename if not necessary" guidance.

No changes were made to `holdout.py`'s logic.
