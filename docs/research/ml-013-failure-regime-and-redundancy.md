# ML-013: Failure-regime and redundancy research (extends ML-012)

Status: complete. Research/analysis only -- no change to the ADR-006 locked
production model, its features, or its hyperparameters.

Machine-readable reports:
`reports/experiments/ml-013-failure-regimes.json` and
`reports/experiments/ml-013-redundancy.json` (generated by
`scripts/ml013_failure_regime_and_redundancy.py`, build `a910017bac839af5`,
`random_state=0`).

This task extends ML-012 (`docs/research/ml-012-feature-ablation.md`,
`reports/experiments/ml-012-feature-ablation.json`), which already established
the real Gold family taxonomy (`team`/`starter`/`bullpen`/`rest_schedule`),
per-family KEEP/INVESTIGATE verdicts, and a univariate leakage scan. Nothing
ML-012 already measured is recomputed here.

## 1. Goal

Two things ML-012 did not cover:

1. **Failure-regime analysis** -- where the locked V1 XGBoost does well or
   poorly, sliced by favorite/underdog, actual home/away outcome, predicted-
   probability bucket, market-edge bucket, starter-quality regime, bullpen-
   workload regime, and season/fold.
2. **Deeper redundancy analysis** -- pairwise/group feature correlation
   (not just ML-012's univariate-vs-target scan), missingness, per-season
   coverage stability, and whether ML-012's per-family ablation benefit is
   concentrated in one fold or spread across folds.

## 2. Methodology

**Model/window under test.** The ADR-006 **locked** model, exactly as
production runs it: tuned shallow XGBoost, **expanding** window (the
production training scheme per `state/CURRENT.md`: "tuned shallow XGBoost +
expanding window + uncalibrated probabilities"), never retuned here.
`experiments.failure_regimes.locked_model_predictions` reuses
`experiments.ablation.LOCKED_XGBOOST` (the ADR-006 hyperparameters, hardcoded
verbatim, identical to ML-012) and `evaluation.runner.run_evaluation(...,
return_predictions=True)` unmodified -- no new fold logic, no new model code.

**Predictions.** 9,694 out-of-sample predictions across the four expanding
folds (test seasons 2022-2025), the same pooled count ML-012's
`leave_one_out:full`/expanding row reports.

**Slice-definition choices (documented explicitly).** Every slice partitions
the 9,694 predictions into real, non-overlapping groups and reports plain,
unmodified `(p_home_win, y_true)` metrics within each group -- **never** a
per-game "reframe to the favorite's own perspective" transform. That
transform was considered and rejected: log loss, Brier, and the calibration
gap are all mathematically invariant under the `p <-> 1-p`, `y <-> 1-y` swap
for a single game (every proper scoring rule is symmetric under it), so
"favorite bucket" vs. "underdog bucket" built that way would report
byte-identical numbers by construction and carry zero information. Instead:

- `favorite_underdog` -- games the model favors home (`p_home_win >= 0.5`,
  `model_favors_home`) vs. favors away (`model_favors_away`). Two genuinely
  different game populations (not a relabeling of the same games).
- `home_away_outcome` -- games actually won by the home team vs. the away
  team (conditions on the true label).
- `probability_bucket` -- 10 equal-width bins over `[0, 1]`, the same
  convention `evaluation.runner._expected_calibration_error` already uses.
- `edge_bucket` -- `p_home_win - no_vig_opening_market_p_home`, for games with
  a MATCHED DATA-009 archive mapping (10,969 of 12,118 certified-build games;
  matching restricted to the certified build's own 2021-2025 game_pk set).
  Reuses `validation.odds_mapping` (DATA-009 matching, unmodified) and
  `market.engine.no_vig_two_way`/opening-market conventions (MARKET-001,
  unmodified) read-only -- no new matching or market math was written. One
  sportsbook line per game (DraftKings preferred, else the alphabetically
  first book with a usable opening pair, mirroring
  `scripts/daily_predictions.py`'s DraftKings pin), not an average across
  books -- a deliberate simplification (documented, not silent): 9,694 of the
  10,969 matched games are in-scope test predictions, of which 8,784 (90.6%)
  resolved a usable edge; 910 lacked a usable opening-price pair for the
  chosen book and are excluded only from this dimension (`n_excluded`).
- `starter_quality_regime` / `bullpen_workload_regime` -- empirical terciles
  (low/mid/high, computed from the evaluated rows themselves, not a
  hand-picked magic threshold) of `diff_starter_season_era_before` (home ERA
  minus away ERA; negative = home starter has the better/lower ERA) and
  `diff_bullpen_bullpen_ip_L7` (home minus away recent bullpen innings).
- `season_fold` -- the expanding fold's `test_season` (2022-2025).

Every slice's sample size is reported explicitly; any slice with
`n < 30` (`LOW_N_THRESHOLD`, matching
`features.completeness.MIN_ROWS_FOR_DISTRIBUTION_CHECKS`) is flagged
`low_confidence` rather than omitted.

**Redundancy analysis.** `experiments.redundancy` adds four checks beyond
ML-012's single-column scan, all reusing the certified build / ML-012's own
artifact rather than recomputing:

- `pairwise_correlation_scan` -- Pearson correlation among all 240 feature
  columns (mean-imputed for this descriptive-only scan; never fed to a
  model), `|r| >= 0.9` flagged, connected components grouped via union-find
  into near-duplicate column groups.
- `missingness_report` -- reads `matrix["feature_completeness"]["columns"]`
  `null_rate` **verbatim** from the certified build's own FEAT-006 report;
  not recomputed.
- `per_season_coverage_stability` -- per-column population rate for each of
  the five development seasons; flags a column whose max-minus-min season
  population rate exceeds 0.2 (a whole-build average, as FEAT-006 already
  reports, could hide a single bad season).
- `ablation_fold_concentration` -- **re-reads**
  `reports/experiments/ml-012-feature-ablation.json`'s existing
  `fold_metrics` (ML-012's ablation is never rerun); for each
  `(family, window)`, computes the per-fold log-loss delta between the
  `leave_one_out:full` and `leave_one_out:<family>` variants and whether one
  fold accounts for more than 50% of the total absolute delta.

**2026 holdout.** Never read. `locked_model_predictions` raises if any fold
carries `test_season == 2026` (redundant with `evaluation.splits`'
structural exclusion, same belt-and-suspenders pattern as
`experiments.ablation._assert_no_holdout`); `pairwise_correlation_scan` and
`per_season_coverage_stability` raise if any input row's season is 2026; the
market-edge join restricts matched games to the certified build's own
2021-2025 `game_pk` set before any lookup (the DB also contains 2026 games
per ML-010, so a stray 2026 archive match is structurally impossible to reach
the output, not just untested).

## 3. Failure-regime results

### 3.1 Favorite / underdog (which side the model favors)

| Group | n | avg predicted P(home) | actual home-win rate | calibration gap | log loss | Brier | ROC-AUC |
|---|---|---|---|---|---|---|---|
| model_favors_home | 5,814 | 0.5910 | 0.5781 | 0.0129 | 0.6766 | 0.2418 | 0.5563 |
| model_favors_away | 3,880 | 0.4373 | 0.4572 | 0.0199 | 0.6882 | 0.2475 | 0.5400 |

The model is measurably weaker specifically when it favors the away team:
lower ROC-AUC (0.540 vs. 0.556), higher log loss, and a 50% larger
calibration gap -- and this is not a small-sample artifact (n=3,880). See
Section 5, recommendation 3.

### 3.2 Actual home/away outcome

| Group | n | avg predicted P(home) | log loss | Brier |
|---|---|---|---|---|
| home_win (y=1) | 5,135 | 0.5428 | 0.6270 | 0.2181 |
| away_win (y=0) | 4,559 | 0.5145 | 0.7423 | 0.2733 |

Calibration gap here is definitional (|avg_p - 1| / |avg_p - 0|, since the
group is defined by the outcome itself) and not independently actionable; it
mainly confirms the model's average predicted probability is only mildly
higher for games home actually wins (0.543) than for games home actually
loses (0.515) -- consistent with the weak overall discrimination already
documented (full-model ROC-AUC ~0.58).

### 3.3 Predicted-probability buckets (10 equal-width bins)

| Bucket | n | avg predicted | actual win rate | calibration gap | log loss | Brier | flag |
|---|---|---|---|---|---|---|---|
| 0.20-0.30 | 33 | 0.2873 | 0.4545 | 0.1673 | 0.7441 | 0.2729 | low_confidence (n<30 borderline, kept) |
| 0.30-0.40 | 791 | 0.3683 | 0.3881 | 0.0198 | 0.6707 | 0.2388 | |
| 0.40-0.50 | 3,056 | 0.4568 | 0.4751 | 0.0184 | 0.6922 | 0.2495 | |
| 0.50-0.60 | 3,514 | 0.5469 | 0.5470 | 0.0001 | 0.6880 | 0.2474 | |
| 0.60-0.70 | 1,874 | 0.6430 | 0.6078 | 0.0352 | 0.6703 | 0.2386 | |
| 0.70-0.80 | 425 | 0.7262 | 0.7059 | 0.0203 | 0.6076 | 0.2083 | |
| 0.80-0.90 | 1 | 0.8036 | 0.0000 | 0.8036 | 1.6278 | 0.6458 | **low_confidence (n=1)** |

The model almost never predicts outside roughly [0.30, 0.80] -- expected
given the documented weak overall edge (ROC-AUC ~0.58). The single `0.80-0.90`
prediction is flagged low-confidence per the task's explicit
"flag, don't omit" requirement and should not be read as evidence the model
is unreliable at high confidence; there is only one such prediction in five
seasons. The best-calibrated bucket by far is `0.50-0.60` (gap 0.0001, right
where most predictions land); the `0.20-0.30` bucket's large gap (0.167) is
on a small (n=33) sample and should be treated cautiously.

### 3.4 Market-edge buckets (model P(home) minus no-vig opening market P(home))

| Bucket | n | avg predicted | actual win rate | calibration gap | log loss | Brier | ROC-AUC |
|---|---|---|---|---|---|---|---|
| model_much_lower_than_market (edge < -0.05) | 1,983 | 0.4793 | 0.5784 | **0.0991** | 0.6899 | 0.2483 | 0.5875 |
| model_slightly_lower_than_market (-0.05..0) | 2,368 | 0.5162 | 0.5296 | 0.0134 | 0.6730 | 0.2401 | 0.6091 |
| model_slightly_higher_than_market (0..0.05) | 2,368 | 0.5461 | 0.5148 | 0.0313 | 0.6756 | 0.2413 | 0.6107 |
| model_much_higher_than_market (edge > 0.05) | 2,065 | 0.5785 | 0.5090 | **0.0695** | 0.6902 | 0.2484 | 0.5907 |

n_excluded = 910 (no usable opening price for the chosen book).

This is the sharpest failure regime found in this study: calibration gap is
5-7x larger in the two "model diverges strongly from market" buckets (0.070,
0.099) than in the two "model roughly agrees with market" buckets (0.013,
0.031), and both large-divergence buckets skew in the direction of the
**market**, not the model -- when the model is much lower than the market,
home teams win MORE than the model predicted (0.578 actual vs. 0.479
predicted); when the model is much higher than the market, home teams win
LESS than the model predicted (0.509 actual vs. 0.579 predicted). In both
large-divergence cases the outcome moved toward the market's view, away from
the model's. See Section 5, recommendation 1.

### 3.5 Starter-quality regime (empirical tercile of home-minus-away starter ERA)

| Group | n | avg predicted | actual win rate | calibration gap | log loss |
|---|---|---|---|---|---|
| low_tercile (home starter ERA advantage) | 2,808 | 0.5685 | 0.5623 | 0.0062 | 0.6716 |
| mid_tercile | 2,869 | 0.5276 | 0.5406 | 0.0130 | 0.6815 |
| high_tercile (away starter ERA advantage) | 2,847 | 0.4952 | 0.4914 | 0.0038 | 0.6890 |
| missing (no prior-season ERA for one/both starters) | 1,170 | 0.5237 | 0.5179 | 0.0058 | 0.6848 |

All four groups are reasonably well-calibrated (gaps 0.004-0.013); no
regime stands out as a failure pocket. The `missing` group (~12% of
predictions, cold-start starters with no prior-season ERA) performs in line
with the populated terciles, not visibly worse -- the model does not appear
to be quietly failing on cold-start-starter games in this development window.

### 3.6 Bullpen-workload regime (empirical tercile of home-minus-away recent bullpen IP)

| Group | n | avg predicted | actual win rate | calibration gap | log loss |
|---|---|---|---|---|---|
| low_tercile (home bullpen used more) | 3,148 | 0.5523 | 0.5543 | 0.0020 | 0.6764 |
| mid_tercile | 3,225 | 0.5279 | 0.5281 | 0.0002 | 0.6828 |
| high_tercile (away bullpen used more) | 3,321 | 0.5094 | 0.5080 | 0.0014 | 0.6844 |

All three groups are near-perfectly calibrated (gap <= 0.002); no bullpen-
workload regime is a failure pocket. Combined with Section 4's finding that
several bullpen-workload columns are near-duplicates of each other, this is
consistent with the bullpen family carrying real but modest, evenly-
distributed signal -- not a hidden failure mode, and not (on this evidence) a
regime that would benefit from a different bucketing.

### 3.7 Season / fold

| Season | n | avg predicted | actual win rate | calibration gap | log loss | ROC-AUC |
|---|---|---|---|---|---|---|
| 2022 | 2,424 | 0.5462 | 0.5330 | 0.0132 | 0.6782 | 0.5975 |
| 2023 | 2,423 | 0.5287 | 0.5200 | 0.0087 | 0.6819 | 0.5870 |
| 2024 | 2,422 | 0.5212 | 0.5223 | 0.0011 | 0.6796 | 0.5885 |
| 2025 | 2,425 | 0.5218 | 0.5435 | 0.0217 | 0.6853 | 0.5645 |

Reproduces ML-011's already-documented pattern (mild degradation on the most

interpretation (season drift and/or weak signal), not a new finding on its
own but a useful cross-check that this harness reproduces known numbers.

## 4. Redundancy findings

### 4.1 Pairwise/group correlation (236 non-constant columns scanned, 27,730 pairs, `|r| >= 0.9`)

108 pairs flagged, forming **39 near-duplicate groups** (23 pairs, 12
triples, 3 quadruples, 1 group of 10). All are explainable, expected
feature-engineering overlap, not leakage (Section 5):

- **The largest group (10 columns)**: `{team}_{games_played,wins,losses,
  runs_scored_total,runs_allowed_total}_before`, home and away separately.
  Season-cumulative win/loss/runs counts are, unsurprisingly, nearly
  collinear with each other (a team that has played more games has
  proportionally more wins, losses, and runs of both kinds).
- **Cross-family near-duplicates**: `{team,bullpen}_games_L{7,14,30}`
  (4-column groups, home+away) -- "games the team played" and "games the
  bullpen appeared in" over the same recent window are nearly identical,
  because a bullpen appears in almost every game. This is a concrete,
  column-level version of ML-012's Section 5.2 finding that `bullpen` and
  `rest_schedule` (both encoding recent bullpen usage) partially overlap --
  here the overlap crosses `team` and `bullpen` too.
- **Same-quantity, different-units triplets**: `bullpen_{ip,outs,pitches}_
  prior_{1d,3d}` and `starter_roll_{starts,ip_per_start}_L{3,5,10}` -- innings
  pitched, outs recorded, and pitches thrown over the identical window are
  near-perfectly redundant representations of the same underlying workload
  (they are almost linear transforms of each other by baseball's own rules:
  3 outs/inning, a roughly stable pitches/out rate). Same for `L3`/`L5`/`L10`
  rolling starts counts, which mostly overlap by construction (a 5-start
  window mostly contains the same starts as a 10-start window early in a
  pitcher's usage history).
- **`avg` vs. `total` pairs**: `team_run_diff_avg_L{7,14,30}` vs.
  `team_run_diff_total_L{7,14,30}` -- an average and a total over a
  near-fixed window size are near-perfectly correlated by construction.

None of the 39 groups mixes columns from different underlying quantities in a
way that looks like a target proxy or postgame value; every flagged pair is
two different *representations* of the same pregame quantity. See Section 5.

### 4.2 Missingness

135 of 240 columns (56%) have at least one missing value across the 12,118
development rows -- read directly from the certified build's own FEAT-006
completeness report, not recomputed. The highest null rates are all
`starter` family columns tied to prior-season starter history
(`diff_starter_season_*_before`, 12.29% null each) -- the same, already-known
cold-start-starter pattern Section 3.5's `missing` regime bucket (n=1,170)
corresponds to. No column is entirely null (that would already FAIL FEAT-006
and could never reach this study).

### 4.3 Per-season coverage stability

**Zero columns** exceed the 0.2 max-minus-min population-rate-across-seasons
threshold. Every column's population rate is stable season to season; the
2021-2025 development window has no season-specific coverage regression that
a whole-build average (Section 4.2) would have hidden.

### 4.4 Fold-concentration of ML-012's per-family ablation benefit

Re-read from `reports/experiments/ml-012-feature-ablation.json:fold_metrics`
(ablation itself was not rerun). `max_fold_share_of_total_abs_delta` is the
largest single fold's share of the total `|leave_one_out:<family> log_loss -
leave_one_out:full log_loss|` across that window's folds; `> 0.5` is flagged
`concentrated_in_one_fold`.

| Family | expanding (4 folds) | rolling_2 (2 folds) | rolling_3 (2 folds) |
|---|---|---|---|
| team | 0.497 (spread) | 0.798 (concentrated*) | 0.702 (concentrated*) |
| starter | 0.412 (spread) | 0.960 (concentrated*) | 0.982 (concentrated*) |
| bullpen | 0.471 (spread) | 0.609 (concentrated*) | 0.775 (concentrated*) |
| rest_schedule | **0.566 (concentrated)** | 0.999 (concentrated*) | 0.986 (concentrated*) |

**Important caveat, stated plainly**: `rolling_2`/`rolling_3` each have only
**2** folds (ML-004's fixed test-season set for those windows), and with 2
folds the larger fold's share of the total is *mechanically* >= 0.5 unless
the two deltas happen to be exactly equal -- so "concentrated" on those two
columns is close to guaranteed by the fold count, not a meaningful finding,
and is marked `(concentrated*)` above to flag that. The **expanding** window
(4 folds, the ADR-006-selected window) is the only column here with real
statistical content: `team`, `starter`, and `bullpen` are all close to an
even 4-fold spread (0.41-0.50), but **`rest_schedule` is the one family whose
expanding-window benefit is measurably more concentrated in a single fold**
(0.566). This sharpens ML-012's existing `rest_schedule` INVESTIGATE verdict
with new, fold-level evidence (ML-012 only compared across the three window
schemes, not across individual folds within a window) -- see Section 5,
recommendation 2.

## 5. Leakage review

**No leakage found; not escalated as P0/P1.** Two checks:

- **Correlation groups (Section 4.1)**: manually reviewed all 39 groups.
  Every one pairs two *different representations of the same pregame
  quantity* (a count vs. a rate, innings vs. outs vs. pitches, `L5` vs. `L10`
  rolling windows) -- normal, expected feature-engineering overlap, not a
  postgame-derived column or a target proxy. This is a redundancy finding,
  not a leakage finding, and does not change ML-012's own leakage verdict
  (Section 4 of `docs/research/ml-012-feature-ablation.md`: 0 columns
  flagged by the univariate scan).
- **Failure-regime results (Section 3)**: no slice shows an implausibly
  strong signal (best slice-level ROC-AUC across all dimensions here is
  0.611, in the two market-edge-agreement buckets -- still in the same weak-
  signal range as the full model's ~0.58-0.59, not a leakage-magnitude jump).

## 6. Top-3 recommended next experiments

Independently justified against THIS study's own findings (not ML-012's
list, which recommended park factors, handedness/platoon splits, and
per-pitcher bullpen availability):

1. **Evaluate a market-informed correction (post-hoc blend or an explicit
   market-probability input feature)** -- motivated directly by Section 3.4:
   calibration gap is 5-7x larger specifically where the model diverges most
   from the no-vig opening market, and both large-divergence buckets moved
   toward the market's view, not the model's. Point-in-time availability:
   already point-in-time safe for the *archived opening-market* backtest
   version used here (ADR-004); a **live** pregame version would additionally
   need to respect ADR-002's snapshot-timing discipline (`snapshot_timestamp
   < prediction_timestamp < first pitch`), which is a real, flagged
   constraint, not a free upgrade. Engineering effort: low (MARKET-001's
   no-vig math and DATA-009 matching already exist and are reused here
   read-only; ~90% of development games already resolve a usable opening
   price per Section 2). Leakage risk: low for the backtest, moderate for a
   live production wiring (needs the existing ADR-002 guard, not a new one).
   Predictive value: plausibly the highest of the three -- this is the one
   regime in the whole study with a >5x calibration-gap spread.

2. **Consolidate the near-duplicate bullpen-workload column triplets found in
   Section 4.1, and re-run ML-012's leave-one-out ablation restricted to
   `rest_schedule` vs. a de-duplicated `rest_schedule`** -- motivated by two
   NEW pieces of evidence this study adds beyond ML-012's family-level
   ambiguity: (a) the correlation scan found concrete, column-level
   near-duplication (`bullpen_{ip,outs,pitches}_prior_{1d,3d}`, and
   `{team,bullpen}_games_L{7,14,30}` crossing family boundaries), not just a
   qualitative overlap description; (b) `rest_schedule` is the one family
   whose expanding-window (4-fold) ablation benefit is measurably
   fold-concentrated (Section 4.4, 0.566 share) while `team`/`starter`/
   `bullpen` are not -- suggesting some of its apparent value may be noise
   riding on redundant columns rather than a stable signal. Engineering
   effort: very low (a column-selection change against already-ingested
   data, directly testable with ML-012's own unmodified harness). Leakage
   risk: none (pure column reduction of already leakage-tested columns).

3. **Investigate the away-favored subgroup specifically** (Section 3.1): the
   model is measurably weaker when it favors the away team (ROC-AUC 0.540
   vs. 0.556, 50% larger calibration gap), on a non-trivial subgroup
   (n=3,880). ML-012 never conditioned model performance on which side the
   model favors. Candidate follow-up: a home/away-conditional recalibration
   check (does Platt/sigmoid calibration, already implemented in ML-008,
   close this specific gap?) before considering any new feature source.
   Engineering effort: very low (reuses `evaluation.calibration` unmodified,
   just partitioned by this study's own `favorite_underdog` slice). Leakage
   risk: none (post-hoc calibration only, same guarantees as ML-008).

## 7. Known limitations

- The `edge_bucket` dimension uses one sportsbook's opening price per game
  (DraftKings preferred, else the alphabetically first book with a usable
  opening pair), not a cross-book average; a different book-selection policy
  could shift bucket boundaries slightly, though the qualitative finding
  (large-divergence buckets have much worse calibration) is unlikely to be an
  artifact of that choice given the effect size (5-7x).
- `ablation_fold_concentration`'s `rolling_2`/`rolling_3` columns are only
  weakly informative (Section 4.4 caveat): with 2 folds, "concentrated in one
  fold" is close to mechanically guaranteed regardless of the underlying
  data. Only the 4-fold expanding-window column carries real signal here.
- `starter_quality_regime`/`bullpen_workload_regime` terciles are computed
  from the evaluated rows themselves (empirical, not a fixed domain
  threshold); the exact tercile boundaries would shift slightly on a
  different certified build.
- The correlation scan mean-imputes missing values for a purely descriptive
  pass (Section 2); this does not feed any model or selection decision, so it
  does not need to satisfy the train-only-preprocessing rule that model
  fitting does.
- As in ML-012, all effect sizes here are consistent with the
  already-documented weak overall V1 edge
  (`reports/experiments/v1-model-diagnostics.json`) -- most slices show small
  absolute log-loss/Brier differences; the two standout findings (Section
  3.4's edge buckets and Section 3.1's favorite/underdog gap) are the
  exceptions, not the rule.
